# 학원 원생 관리 프로그램 — PRD

- 버전: 0.2
- 작성일: 2026-09-13
- 상태: 요구사항 초안. 대화에서 합의한 범위와 구현을 위한 제안 기본값을 구분한다.
- 대상: 관리자 선생님 1명이 사용하는 영어학원 원생 관리 웹앱

## 1. 목적과 목표

원생별 교재 사용 내역, 날짜별 일지·상담, 시험 성적을 한곳에서 관리한다. 선생님은 노트북과 휴대폰에서 같은 데이터를 조회하고 입력·수정할 수 있어야 한다.

핵심 목표는 다음과 같다.

1. 원생을 찾아 필요한 기록을 빠르게 확인한다.
2. 사용 중이거나 사용 완료한 교재를 확인해 다음 교재 선택에 참고한다.
3. 일지와 상담내용을 날짜가 있는 독립적인 기록으로 축적한다.
4. 같은 시험 카테고리 안에서 성적의 날짜별 추세와 난이도를 확인한다.
5. 기기를 바꾸어도 저장한 기록이 유지된다.

MVP 성공 기준은 9절의 인수 기준을 실제 노트북·휴대폰 환경에서 충족하는 것이다. 예상 원생 수는 약 50명이며 개발은 착수 후 5일 이내 완료를 목표로 한다. 운영비는 최소화하되 필수 지출은 US$10 이내에서 허용한다. 예산 기간은 월간으로 해석한 제안 기본값이며, 호스팅·데이터베이스·인증·백업 등 필수 운영비 합계에 적용한다. 특정 유료 서비스의 실제 가격은 기술 선정 시 확인한다.

## 2. 사용자와 사용 환경

| 구분 | 요구사항 |
|---|---|
| 사용자 | 관리자 선생님 1명 |
| 접속 환경 | 노트북과 휴대폰의 웹브라우저 |
| 화면 | 기기 크기에 맞추는 반응형 화면 |
| 계정 | 관리자 계정 1개, 공개 회원가입 없음 |
| 저장 | 서버의 공용 데이터베이스에 영구 저장 |
| 연결 | 100% 온라인 전용. 모든 데이터 작업에 서버 연결 필요 |
| 권한 | 관리자만 원생 데이터 조회·입력·수정·삭제 가능 |

학생·학부모 계정이나 여러 선생님의 역할별 권한은 MVP에 포함하지 않는다.

## 3. 범위와 결정 상태

### 3.1 합의된 MVP 범위

- 원생 기본정보: 이름 필수, 학교·학년 선택.
- 원생 목록, 이름 검색, 원생 상세 조회와 기본정보 수정.
- 원생별 교재명과 사용 중 / 사용 완료 상태 관리.
- 날짜 필수인 일지·상담 통합 기록의 작성·조회·수정.
- 시험 성적의 입력·조회·수정, 카테고리별 추세 확인.
- 시험 카테고리명 설정. 모든 시험의 만점은 100점으로 고정하며 만점 설정 기능은 제공하지 않는다.
- 원생, 시험 성적, 일지·상담 기록의 삭제. 원생·시험 성적 삭제 전 경고 및 명시적 확인 필수.
- 선택적 시험 난이도 표시.
- 관리자 로그인과 로그아웃, 여러 기기에서 동일 데이터 사용.
- 자동 백업과 복구 가능성 확보.

### 3.2 초안의 제안 기본값

아래는 미세 동작을 구체화하기 위한 제안이며, 사용자가 개별적으로 확정한 사항과 구분한다. 변경 시 관련 요구사항과 인수 기준을 함께 수정한다.

| 항목 | 제안 기본값 |
|---|---|
| 날짜 입력 | 한국 시간 기준 오늘을 기본값으로 사용하고 과거 날짜 입력 허용 |
| 일지·상담 정렬 | 최근 날짜부터 표시, 같은 날짜의 여러 기록 허용 |
| 난이도 | 미입력 / 쉬움 / 보통 / 어려움 |
| 다른 기기의 변경 확인 | 화면 재조회 또는 새로고침 시 최신 저장 내용 반영; 실시간 갱신은 필수 아님 |
| 교재 입력 보조 | 기존 등록 교재명 자동완성은 후속 개선으로 분류 |
| 원생 삭제 범위 | 원생 삭제 시 해당 원생의 교재·일지·상담·성적도 함께 삭제 |
| 삭제 후 복원 | MVP에는 휴지통·개별 복원 화면 없음. 운영 백업 복구와 구분 |
| 예산 기간 | 운영비 합계 월 US$10 이내로 해석 |

### 3.3 MVP 제외 범위

- 전체 교재 카탈로그 구축, 미사용 교재 등록, 교재 재고·구매 관리.
- 출결, 수납, 시간표, 반 관리, 연락처·주소·재원 상태 관리.
- 학생·학부모 접속, 문자·알림 발송, 다중 관리자 권한.
- 교재·성적 변경사항을 일지·상담에 자동으로 기록하는 기능.
- 서로 다른 시험 카테고리 비교, 100점 환산, 난이도에 따른 점수 보정.
- 모든 오프라인 기능: 오프라인 조회·편집·저장, 로컬 데이터베이스, 재연결 자동 동기화, 오프라인 앱 캐시. 네이티브 모바일 앱.
- 100점 이외 만점, 만점 입력·변경, 만점별 추세 분리.
- 휴지통·개별 기록 복원 화면, 시험 카테고리 삭제, 교재 내역의 개별 삭제(원생 삭제 시 함께 제거).
- AI 분석, 첨부파일, 기존 자료 일괄 가져오기, 통계 보고서 자동 생성.

## 4. 주요 사용 시나리오

### S-01. 원생 등록과 기록 확인

관리자가 로그인하고 이름으로 원생을 검색한다. 신규 원생이면 이름을 입력해 등록하고, 필요하면 학교·학년을 추가한다. 원생 상세에서 교재, 일지·상담, 성적 중 원하는 영역을 연다.

### S-02. 교재 사용 여부 확인

원생의 교재 목록에서 기존 사용 여부를 확인한다. 새로 사용하기 시작한 교재는 교재명을 입력하고 사용 중으로 등록한다. 학습을 마치면 사용 완료로 변경한다. 목록에 없는 교재를 시스템이 미사용으로 확정하지 않는다.

### S-03. 일지 또는 상담 기록 작성

원생의 일지·상담 영역에서 날짜와 내용을 입력하고 저장한다. 교재나 성적을 선택할 필요가 없다. 같은 날짜의 추가 상담도 별도 기록으로 남길 수 있다. 이후 날짜순 목록에서 확인하고 수정한다.

### S-04. 시험 성적 입력과 추세 확인

원생의 성적 영역에서 시험 카테고리를 선택하고 시험일·시험명·점수를 입력한다. 만점은 모든 카테고리에서 100점으로 고정되어 별도 입력하지 않는다. 난이도는 선택적으로 입력한다. 저장 후 해당 카테고리의 기록 목록과 날짜순 그래프에서 확인한다.

### S-05. 기기를 바꾸어 사용

노트북에서 저장 성공을 확인한 후 휴대폰에서 같은 계정으로 접속해 해당 원생 기록을 조회한다. 휴대폰에서 수정한 내용은 노트북에서 재조회했을 때 반영된다.

### S-06. 기록 삭제

관리자는 원하는 시점에 원생, 시험 성적 또는 일지·상담 기록을 삭제한다. 원생·시험 성적은 경고에서 대상을 확인하고 삭제를 확정해야 한다. 취소하면 유지된다. 일지·상담은 통합 기록의 개별 항목을 삭제한다. 삭제 완료 후 다른 기기에서 재조회해도 해당 항목이 나타나지 않는다.

## 5. 기능 요구사항

### FR-01. 관리자 인증

- 관리자 계정으로 로그인·로그아웃할 수 있다.
- 로그인하지 않은 사용자는 원생 목록, 상세 기록, 관련 데이터 요청에 접근할 수 없다.
- 공개 회원가입과 추가 관리자 생성 화면은 제공하지 않는다.
- 계정 최초 생성과 접근 복구 방식은 기술 설계에서 결정한다.

### FR-02. 원생 기본정보

- 이름은 필수이며 공백만 입력할 수 없다. 학교·학년은 선택이다.
- 원생을 등록하고 기본정보를 수정할 수 있다.
- 이름 검색 결과에 학교·학년을 함께 표시한다. 미입력 항목은 비어 있음을 구분한다.
- 동명이인을 별개의 원생으로 등록할 수 있다. 이름을 데이터 연결 키로 사용하지 않는다.
- 기본정보를 수정해도 기존 교재·일지·성적의 원생 연결은 유지된다.

### FR-03. 원생별 교재 사용 내역

- 원생별로 교재명과 상태를 등록·조회·수정할 수 있다.
- 교재명은 필수이며 상태는 사용 중 또는 사용 완료 중 하나이다.
- 사용 중 / 사용 완료를 목록에서 구분해 표시한다.
- 상태는 양방향으로 수정할 수 있어 잘못된 입력을 바로잡을 수 있다.
- 미사용 상태나 사전 전체 교재 등록을 요구하지 않는다.
- 교재 내역에 사용 시작일·종료일·진도 등의 추가 입력을 요구하지 않는다.

### FR-04. 일지·상담 통합 기록

- 원생별로 날짜와 내용을 필수 입력하여 기록을 작성·조회·수정할 수 있다.
- 날짜 누락과 공백만 있는 내용은 저장을 막고 수정할 항목을 안내한다.
- 날짜는 기록의 대상 날짜이며, 시스템의 생성·수정 시각과 구분한다.
- 일지와 상담을 구분하는 필수 분류나 별도 화면을 두지 않는다.
- 교재·성적이 없어도 기록을 작성할 수 있다. 이들과의 연결을 요구하지 않는다.
- 교재·성적의 입력·수정은 이 기록 영역에 자동 항목을 생성하거나 내용을 변경하지 않는다.
- 제안 기본값: 최근 날짜순으로 표시하고 같은 날짜는 생성 순서가 일관되게 유지되도록 한다. 같은 날짜의 여러 기록을 허용한다.

### FR-05. 시험 카테고리 설정

- 카테고리명을 등록·조회·수정할 수 있다. 이름은 필수이다.
- 모든 카테고리와 시험의 만점은 100점으로 고정한다. 사용자 만점 입력·변경 기능은 제공하지 않는다.
- 공백 제거 후 동일한 이름의 카테고리가 중복 생성되지 않도록 안내한다.
- 초기 카테고리는 아래와 같다.

| 카테고리명 | 고정 만점 |
|---|---:|
| 중학교 내신 영어 | 100 |
| 고등학교 내신 영어 | 100 |
| 수능 영어 | 100 |
| 모의고사 영어 | 100 |
| 영어듣기평가 | 100 |

- 카테고리 이름을 수정해도 기존 성적의 카테고리 연결이 유지된다.
- 카테고리는 시험 종류를 분류하는 용도이며 만점 차이를 표현하지 않는다.

### FR-06. 시험 성적 기록

- 필수 입력 항목은 시험일, 시험명, 카테고리, 점수이다. 난이도는 선택 항목이다.
- 만점은 시스템 공통값 100이며 개별 기록의 가변 항목이 아니다.
- 점수는 0 이상 100 이하여야 한다. 소수 점수를 허용한다.
- 성적을 조회·수정·삭제할 수 있다. 삭제는 FR-09를 따른다.
- 난이도 미입력은 보통과 구분한다. 난이도를 선택하지 않아도 저장할 수 있다.
- 같은 날짜에 여러 시험을 기록할 수 있으며 날짜만으로 기존 기록을 덮어쓰지 않는다.

### FR-07. 성적 추세

- 원생 상세에서 카테고리를 선택하면 해당 원생·카테고리의 기록만 표시한다.
- 그래프는 시험일 오름차순, 점수는 원점수를 사용한다. 기록 목록에 시험명·날짜·점수·만점·난이도를 표시한다.
- 다른 카테고리 기록을 한 그래프에 겹치거나 연결하지 않는다. 환산점수를 계산하지 않는다.
- 난이도는 기록 해석용 정보로 표시하며 점수나 추세를 보정하지 않는다.
- 기록이 없으면 빈 상태 안내, 하나이면 점 하나와 시험 정보를 표시한다.
- 그래프의 점수 축은 0~100으로 고정한다. 만점별 구분 기능은 구현하지 않는다.
- 성적 삭제 후 해당 점을 제외한 기록으로 그래프와 목록을 갱신한다.
- 같은 날짜의 여러 시험은 별도 기록으로 확인할 수 있어야 한다.

### FR-08. 여러 기기에서 저장·조회

- 노트북과 휴대폰 모두 핵심 조회·입력·수정·삭제를 지원한다.
- 서버 저장이 확인된 경우에만 저장 성공을 표시한다.
- 저장 실패 시 오류를 안내하고 현재 화면의 입력값을 유지해 재시도할 수 있게 한다.
- 다른 기기에서 재조회하면 마지막으로 성공한 저장 내용이 표시된다.
- 같은 기록을 두 기기에서 수정했을 때 오래된 편집으로 최신 내용을 조용히 덮어쓰지 않는다. 충돌을 알리고 최신 내용을 다시 확인하도록 한다.
- 100% 온라인으로 동작한다. 연결이 끊기면 데이터 작업을 차단하고 연결 필요 또는 요청 실패를 안내한다.
- 실패 시 현재 폼의 입력값을 메모리에 유지하는 것은 오류 처리일 뿐 오프라인 편집·영구 저장 기능이 아니다. 연결 복구 후 관리자가 직접 재시도한다.
- 오프라인용 데이터 캐시·입력 대기열·자동 재전송·로컬 데이터베이스는 구현하지 않는다. 실시간 푸시 갱신은 필수 기능이 아니다.

### FR-09. 삭제와 확인

- 관리자는 온라인 상태에서 원생, 시험 성적, 일지·상담 기록을 기간·상태 제한 없이 삭제할 수 있다. 일지와 상담은 기존 통합 기록 구조를 유지한다.
- 원생 삭제 전 원생 이름과 학교·학년(있는 경우)을 표시하고 경고한다: “이 원생을 삭제하면 기본정보와 모든 교재 사용 내역, 일지·상담, 시험 성적이 함께 삭제됩니다. 앱에서 되돌릴 수 없습니다. 삭제하시겠습니까?”
- 시험 성적 삭제 전 원생명, 시험명, 시험일, 카테고리, 점수를 표시하고 경고한다: “이 시험 성적을 삭제하면 기록과 성적 추세에서 제거됩니다. 앱에서 되돌릴 수 없습니다. 삭제하시겠습니까?”
- 위 두 대상은 취소 / 삭제 버튼으로 명시적 선택을 받아야 하며 경고 표시만으로 삭제하지 않는다. 취소하면 데이터가 바뀌지 않는다.
- 일지·상담의 개별 기록 삭제에는 추가 경고를 필수로 요구하지 않는다. 삭제한 항목 외의 기록과 교재·성적은 유지한다.
- 원생 삭제 시 종속 기록을 함께 제거하는 것은 제안 기본값이다. 작업은 전부 성공하거나 전부 취소되어 일부 기록만 남지 않아야 한다. 공용 시험 카테고리와 다른 원생 기록은 유지한다.
- 서버에서 삭제가 성공한 경우에만 완료를 표시하고 목록·그래프를 갱신한다. 실패하면 실패를 안내하고 재조회한다.
- 이미 삭제된 기록을 다른 기기에서 수정·삭제하면 삭제된 상태를 안내한다. 오래된 편집으로 기록을 다시 생성하지 않는다.
- 앱에서 삭제한 데이터는 일반 조회·검색에 나타나지 않는다. 백업에 남는 데이터의 보관·만료는 별도 백업 정책을 따른다. 개별 복원 UI는 제공하지 않는다.

## 6. 정보와 화면 구조

### 6.1 논리적 데이터 구성

아래는 필요한 정보의 관계이며 특정 데이터베이스나 물리 스키마를 확정하지 않는다.

| 정보 | 주요 항목 | 관계 |
|---|---|---|
| 원생 | 내부 식별자, 이름, 학교, 학년 | 모든 원생별 기록의 기준 |
| 교재 사용 내역 | 내부 식별자, 원생 식별자, 교재명, 상태 | 원생 1명에 여러 내역 |
| 일지·상담 기록 | 내부 식별자, 원생 식별자, 기록 날짜, 내용 | 교재·성적과 독립 |

생성·수정 시각과 변경 충돌 확인용 정보는 시스템에서 관리하며 사용자에게 입력을 요구하지 않는다. 날짜 필드는 기기 시간대 차이로 하루가 바뀌지 않도록 다룬다.

### 6.2 화면 구성

1. 로그인 화면.
2. 원생 목록: 이름 검색, 원생 등록, 상세 진입.
3. 원생 상세: 기본정보 / 교재 / 일지·상담 / 성적.
4. 설정: 시험 카테고리명 관리.
5. 삭제 동작: 원생·성적의 경고 확인창, 통합 일지·상담 기록의 개별 삭제.

휴대폰에서 필수 입력란과 저장 버튼을 이용할 수 있어야 한다. 일지·상담 화면에 교재·성적 내역을 합친 통합 타임라인을 표시하지 않는다.

## 7. 품질 및 운영 요구사항

| ID | 요구사항 | 확인 방법 |
|---|---|---|

| NFR-03 | 노트북과 휴대폰에서 핵심 작업 수행 가능 | 두 화면 크기에서 등록·조회·수정·삭제 수행 |

원생 약 50명의 데이터를 기준으로 핵심 사용 흐름을 검증한다. 50명은 예상 규모이며 등록 상한은 아니다. 운영 구성은 월 US$10 이내라는 예산 해석에 맞추고 무료 옵션을 우선 검토한다.

백업 주기·보관 기간·저장 위치와 허용 데이터 손실 시간은 배포 전 결정한다. MVP부터 백업을 포함하되, 복잡한 사용자용 백업 관리 화면은 요구하지 않는다. 학생 기록과 인증정보가 공개 파일이나 클라이언트 코드에 포함되지 않도록 한다.

## 8. 예외 처리 원칙

- 다른 원생의 기록이 섞이지 않도록 모든 기록의 원생 연결을 유지한다.
- 입력 오류는 해당 항목 가까이에 원인을 표시한다.
- 데이터가 없는 상태는 로딩 실패와 구분한다.
- 점수 0은 유효한 성적이며 미입력으로 처리하지 않는다.
- 미등록 교재는 미사용으로 단정하지 않는다.
- 모든 시험은 100점 만점으로 검증하며 다른 만점의 예외를 구현하지 않는다.
- 삭제 취소·실패·완료를 구분하며 원생 삭제는 종속 기록과 함께 일관되게 처리한다.

## 10. 5일 이내 구현 계획 제안

| 일정 | 사용자에게 제공되는 결과 | 검증 범위 |
|---|---|---|
| 1일차 | 최소 운영 구조 선정, 로그인, 원생 등록·검색·수정, 온라인 배포 경로 확보 | AC-01~03, 예산 산정 |
| 2일차 | 날짜별 일지·상담 작성·수정·삭제, 기기 간 조회 | AC-05, AC-12~13, AC-17, AC-19 |
| 3일차 | 교재 관리, 카테고리 설정, 100점 고정 성적 입력·수정 | AC-04, AC-06~09 |
| 4일차 | 성적 추세, 성적·원생 삭제 경고, 삭제 후 반영·충돌 처리 | AC-10~11, AC-15~18 |
| 5일차 | 약 50명 기준 전체 검증, 자동 백업·복구 검증, 오류 수정 및 운영 배포 | AC-14, AC-20 및 전체 인수 기준 |

이는 5일 이내 완료를 위한 배분안이며 구현 완료 보장이 아니다. 기능 확장은 이 일정에 추가하지 않는다. 일정 위험이 발생하면 원인과 조정안을 먼저 제시하고 필수 요구사항을 임의로 삭제하지 않는다.

백업 방식은 초기 데이터 저장 설계에서 정하고 실제 학생 데이터를 넣기 전에 구성·복구 검증을 완료한다. 각 단계는 화면·저장·조회까지 연결된 기능 단위로 구현한다.

## 11. 남은 결정과 변경 관리

### 기술 설계 전에 결정할 사항

- 예산의 월간 기준 해석 확인과 예상 기록 누적량. 개발 5일 이내·원생 약 50명·US$10 이내 조건은 확정.
- 호스팅, 데이터베이스, 인증 방식, 관리자 계정 생성·접근 복구 방식.
- 백업 주기·보관 기간·복구 절차와 허용 데이터 손실 범위.

### 해당 기능 구현 전에 확인할 사항

- 난이도 선택지: 3.2절의 제안 기본값으로 검토한다.
- 원생 삭제 시 종속 기록 함께 삭제 및 개별 복원 화면 제외는 제안 기본값이다. 원생·성적·일지·상담 삭제 지원과 원생·성적 삭제 경고는 확정이다.

이 PRD는 제품 동작의 기준 문서다. 기술 선택과 배포 절차는 이후 DESIGN.md에서 구체화한다. 구현 중 새로운 기능이 필요하면 현재 범위에 자동 추가하지 않고 변경 후보로 기록한다. 요구사항과 구현이 충돌하면 충돌을 알리고 결정 후 문서를 갱신한다.
