# 원생노트 기술 설계 및 검증 상태

PRD v0.2에 따른 초기 구현입니다. PRD 원문은 변경하지 않았습니다.

## 적용한 기본값

한국 시간 기준 오늘, 과거 날짜 허용, 일지 최근 날짜순(같은 날 ID 역순), 난이도 미입력/쉬움/보통/어려움, 원생 삭제 시 종속 기록 삭제, 휴지통 없음, 월 US$10 예산 해석을 적용했습니다. 날짜는 YYYY-MM-DD 문자열로 저장하여 시간대 변환을 하지 않습니다.

## 구조

Python 표준 라이브러리 HTTP 서버와 SQLite, HTML/CSS/JavaScript로 구성합니다. 런타임 외 패키지 의존성 없이 실행됩니다. 단일 서버의 영구 디스크에 DB를 두며 모든 기기가 같은 서버를 사용합니다. 여러 서버 복제본이나 임시 디스크를 사용하는 서버리스 배포는 이 구성에 맞지 않습니다.

- `academy/server.py`: 인증, REST API, 데이터 검증, SQLite 트랜잭션, 비밀번호 관리, 백업
- `static/`: 한국어 반응형 UI, 폼, 삭제 확인창, SVG 성적 그래프
- `tests/test_app.py`: 실제 HTTP 요청을 사용하는 통합 테스트

모든 API는 로그인 검사를 거칩니다(로그인 요청 제외). 정적 로그인 셸에는 학생 데이터가 없습니다. HttpOnly/SameSite 쿠키와 별도 CSRF 토큰을 사용하며 세션은 12시간 유지합니다. 운영 시 `--secure`로 Secure 쿠키를 활성화합니다. 비밀번호는 무작위 salt와 scrypt(N=16384, r=8, p=5)로 해시하고 최초 설정·복구는 서버 터미널에서 수행합니다. `set-password`가 `.env`의 `ADMIN_PASSWORD_HASH`를 권한 600으로 원자적으로 저장하고 DB 인증값을 동기화합니다. 서버 시작 시 `.env`를 필수로 읽으며 설정 오류·느슨한 파일 권한은 시작을 차단합니다. 인증값 변경 시 기존 세션을 종료합니다. `.env`는 Git에 포함하지 않고, 별도 경로는 `--env-file`로 지정합니다. 공개 가입 기능은 없습니다. 로그인 시도는 서버 전체 5분당 10회로 제한합니다(재시작 시 초기화).

각 테이블은 내부 ID와 정수 버전을 사용합니다. 수정·삭제는 쓰기 트랜잭션 안에서 전달된 버전을 비교합니다. 충돌은 409, 이미 삭제된 대상은 404이며 새 기록으로 재생성하지 않습니다. 학생 삭제는 외래 키 CASCADE로 일괄 처리합니다. 시스템 생성·수정 시각은 `audit_times`에서 UTC로 관리합니다. 이 테이블은 변경 이력 보관용이 아니며 삭제된 기록의 내용은 남기지 않습니다.

입력은 서버에서 필드 허용 목록으로 검증합니다. 점수는 유한한 0~100 숫자만 허용하고 가변 만점 필드는 거부합니다. 카테고리명은 앞뒤 공백 제거 후 중복을 막습니다. 성적 그래프는 한 카테고리만 시험일·ID 오름차순으로 표시합니다. 같은 날짜의 시험은 겹치지 않게 순서대로 배치하므로 가로 간격은 경과 일수에 비례하지 않습니다. 전체 시험 날짜와 난이도는 목록과 점의 설명에서 확인합니다.

모든 응답은 `no-store`입니다. localStorage, IndexedDB, 서비스 워커, 자동 재전송은 없습니다. 브라우저가 오프라인을 감지하면 데이터 화면과 폼을 가리고 연결 안내를 표시합니다. 서버 요청 실패 시 성공 안내를 하지 않고 현재 폼 입력을 유지합니다. 연결 복구 후 수동 새로고침 또는 재시도가 필요합니다.

## 배포 경로와 비용

개발 서버는 기본으로 loopback에만 바인딩합니다. 운영 시 HTTPS 역방향 프록시 뒤에서 실행하고 HTTP 서버 포트를 인터넷에 직접 노출하지 않습니다. 프록시는 TLS 종료, 연결/요청 제한, 타임아웃을 담당해야 합니다. 서비스 프로세스는 전용 OS 계정과 자동 재시작 설정으로 운영합니다.

```bash
python3 -m academy.server --host 127.0.0.1 --port 8000 --secure --db /srv/academy/data/academy.sqlite3 --backups /srv/academy/backups
```

배포 업체·도메인·외부 저장소는 아직 선정하거나 구매하지 않았습니다. 소프트웨어 자체의 추가 유료 서비스 의존성은 없지만, 실제 호스팅·영구 디스크·HTTPS 도메인·외부 백업 합계가 월 US$10 이내인지는 배포 전 현재 가격으로 확인해야 합니다. 따라서 AC-20 비용 항목과 운영 배포는 완료로 표시하지 않습니다.

## 백업 정책 제안

서버 시작 시 및 24시간마다 SQLite 온라인 백업 API로 일관된 스냅샷을 생성합니다. 보관 기간은 30일, 정상 실행 중 목표 최대 데이터 손실은 24시간입니다. 중단 중에는 예약 작업이 실행되지 않습니다. 백업 실패는 콘솔 메시지로 알리며 별도 모니터링 연결은 운영 시 필요합니다.

기본 백업 경로는 같은 디스크이므로 디스크 전체 장애를 보호하지 못합니다. 운영 전 `--backups`를 보호된 별도 볼륨으로 지정하고, 암호화된 서버 외부 저장소에 매일 복사하는 작업을 구성해야 합니다. 해당 저장소의 30일 보관 정책과 접근 권한도 별도 설정합니다. 실제 외부 저장소는 아직 연결하지 않았습니다. 백업 자체에 학생 기록과 비밀번호 해시가 포함되어 공개 경로에 두면 안 됩니다.

복구 절차는 README에 있습니다. 자동 백업과 수동 백업은 같은 함수를 사용합니다. 통합 테스트는 이 함수를 실행해 50명과 교재·일지·성적을 백업하고 별도 DB로 재개방하여 무결성과 외래 키 관계, 세션 제거를 확인합니다. 실제 24시간 예약 실행과 서버 외부 복구 훈련은 아직 수행하지 않았습니다.

## 검증 상태

자동 통합 테스트 3개 시나리오 통과:

- 인증 없는 모든 데이터 API 차단, CSRF 차단, 로그아웃 이후 차단
- 동명이인, 필수 입력, 카테고리 중복, 0점·소수·범위 제한·가변 만점 거부, 교재 상태 양방향 변경
- 동일 날짜 독립 기록, 수정 충돌, 오래된 삭제 충돌, 삭제 기록 재생성 차단, 원생 삭제의 종속 제거와 다른 원생/카테고리 보존
- 가상 원생 50명 및 기록 저장, 백업 무결성·관계 검증, 복구 DB 재개방

Python 컴파일과 JavaScript 구문 검사를 통과했습니다. 브라우저 자동화 도구가 제공되지 않아 실제 화면의 상호작용과 레이아웃 검증은 수행하지 않았습니다. 구현된 화면 기능을 실제 기기 검증 완료로 간주하지 않습니다.

남은 인수 검증:

1. 노트북과 휴대폰에서 같은 HTTPS 서버에 접속해 AC-01~20의 전체 화면 흐름 수행.
2. 0개/1개/같은 날짜 여러 성적 그래프와 각 범주의 분리, 삭제 취소 및 삭제 후 그래프 확인.
3. 두 브라우저에서 같은 기록 수정, 요청 차단 시 폼 입력 유지, 오프라인 안내 확인.
4. HTTPS·영구 디스크·프로세스 자동 재시작·외부 백업 구성, 예약 백업과 별도 환경 복구.
5. 업체의 실제 월 비용 합계 확인 후 운영 배포.

비밀번호 저장 설정 근거: [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). 추가 통합 테스트로 해시 저장, 파일 권한, 비밀번호 교체 후 이전 로그인·세션 차단, 잘못된 설정 거부, 새 DB 인증값 동기화를 검증합니다.
